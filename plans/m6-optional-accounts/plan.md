# M6 — حساب کاربری اختیاری

**هدف:** افزودن شخصی‌سازی **بدون** تحمیل ثبت‌نام. طبق `features.md` ثبت‌نام اختیاری است و فقط وقتی پیشنهاد می‌شود که کاربر به علاقه‌مندی یا هشدار قیمت نیاز داشته باشد.

**نتیجه قابل اندازه‌گیری:** کاربر با OTP وارد می‌شود، کالا را به علاقه‌مندی اضافه می‌کند، هشدار کاهش قیمت می‌گذارد و هنگام افت قیمت اعلان می‌گیرد.

**وابستگی:** M2 (صفحه کالا و offer) و M5 (قیمت معتبر؛ هشدار روی قیمت مشکوک ارسال نمی‌شود).

## آیتم‌ها

### [PH1-039] ورود با OTP
**تخمین:** L — **نقش اجرا:** backend-dev

- [x] ارسال کد به شماره موبایل با طول عمر کوتاه و انقضای صریح.
- [x] کد **هش‌شده** ذخیره می‌شود و مقایسه با زمان ثابت انجام می‌گیرد.
- [x] کد پس از یک بار استفاده باطل می‌شود.
- [x] محدودیت نرخ ارسال به‌ازای شماره و به‌ازای IP، با پیام فارسی روشن هنگام عبور از سقف.
- [x] شماره موبایل در لاگ ماسک می‌شود و کد OTP هرگز لاگ نمی‌شود.
- [x] شماره نامعتبر پیش از ارسال رد می‌شود.
- [x] رویدادهای `otp.sent`، `otp.verified`، `otp.rate_limited` لاگ می‌شوند.

### [PH1-040] سشن کاربر
**تخمین:** M — **نقش اجرا:** backend-dev

- [x] سشن با کوکی `HttpOnly` + `Secure` + `SameSite=Lax` و انقضای مشخص.
- [x] نقش `user` هیچ دسترسی‌ای به مسیرهای `/ops` و `/admin` ندارد (تست شده).
- [x] خروج از حساب سشن را باطل می‌کند.
- [x] هیچ توکنی در `localStorage` نگه‌داری نمی‌شود.
- [x] کاربر مهمان همه‌ی قابلیت‌های هسته (جست‌وجو، مقایسه، خرید) را بدون ورود دارد.

### [PH1-041] لیست علاقه‌مندی
**تخمین:** M — **نقش اجرا:** frontend-dev + backend-dev

- [x] افزودن و حذف کالا از علاقه‌مندی با Server Action.
- [x] صفحه‌ی علاقه‌مندی‌ها با کم‌ترین قیمت فعلی هر کالا.
- [x] کلیک روی افزودن در حالت مهمان، جریان ورود را پیشنهاد می‌دهد و **پس از ورود همان کالا ذخیره می‌شود** (قصد کاربر گم نشود).
- [x] افزودن تکراری خطا نمی‌دهد (idempotent).
- [x] حالت خالی با پیشنهاد جست‌وجو.

### [PH1-042] ثبت هشدار قیمت و موجودی
**تخمین:** M — **نقش اجرا:** frontend-dev + backend-dev

- [x] کاربر می‌تواند هشدار «کاهش قیمت» یا «موجود شدن» برای یک کالا ثبت کند.
- [x] امکان تعیین قیمت هدف (اختیاری).
- [x] سقف تعداد هشدار فعال برای هر کاربر.
- [x] مدیریت و حذف هشدارها در حساب کاربری.

### [PH1-043] ارزیابی و ارسال هشدار
**تخمین:** L — **نقش اجرا:** backend-dev

- [x] job دوره‌ای، هشدارها را در برابر `price_history` و موجودی ارزیابی می‌کند.
- [x] هشدار روی offer `suspicious` یا کهنه ارسال **نمی‌شود**.
- [x] هر هشدار برای یک رویداد فقط یک بار ارسال می‌شود (بدون اعلان تکراری).
- [x] ارزیابی به‌صورت دسته‌ای و بدون N+1 انجام می‌شود.
- [x] شکست ارسال، هشدار را حذف نمی‌کند؛ با backoff دوباره تلاش می‌شود و سقف تلاش دارد.
- [x] رویدادهای `alert.triggered` و `alert.sent` لاگ می‌شوند.

### [PH1-044] رابط کاربری حساب
**تخمین:** M — **نقش اجرا:** frontend-dev

- [x] صفحه ورود با ورودی OTP: `type="tel"`، `inputMode="numeric"`، `autoComplete="one-time-code"`.
- [x] نمایش شمارش معکوس ارسال مجدد و پیام محدودیت نرخ.
- [x] دکمه در زمان ارسال غیرفعال می‌شود تا ارسال تکراری رخ ندهد.
- [x] صفحه حساب کاربری: علاقه‌مندی‌ها، هشدارها، خروج.
- [x] کامپوننت‌های تعاملی فقط برگ درخت‌اند و صفحات عمومی را کلاینتی نمی‌کنند.

## خارج از دامنه

پروفایل کامل کاربر، نظرات و امتیازدهی، اشتراک‌گذاری اجتماعی، اعلان مرورگر (Web Push)، سبد خرید و سفارش. هیچ‌کدام در `features.md` فاز اول نیستند.

## ریسک

- **اجباری‌شدن ناخواسته‌ی ثبت‌نام:** هر جریانی که کاربر مهمان را از مسیر خرید بیرون کند نقض `features.md` است.
- **هزینه و محدودیت درگاه پیامک:** محدودیت نرخ و پیش‌بینی هزینه پیش از انتشار بررسی شود.
- **سوءاستفاده از ارسال OTP:** بدون محدودیت نرخ درست، این نقطه هم هزینه‌ساز است و هم مسیر آزار.
- **اعلان اشتباه به‌خاطر قیمت غلط:** به‌همین دلیل M5 پیش‌نیاز این Milestone است.
